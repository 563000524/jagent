# 办公智能体 概要设计

> 版本 v0.1 ｜ 形态：Windows 桌面应用（内嵌 JRE）｜ 技术栈：JavaFX + WebView + Vue 3 + Spring Boot 3.3

---

## 1. 项目定位

面向企业办公场景的**桌面端 AI 助手**。以聊天框为唯一入口，通过「大模型 + 工具调用 + 企业知识库」完成公文写作、会议纪要、数据汇总、事务办理等日常办公任务。

**设计原则**

| 原则 | 说明 |
| --- | --- |
| 单机优先 | 开箱即用，双击即用，无需独立部署服务端 |
| 本地数据 | 会话、配置、知识索引全部存本机，不出内网 |
| 模型无关 | 走 OpenAI 兼容协议，供应商可切换（硅基流动 / DeepSeek / OpenAI / Ollama 本地） |
| 能力可插拔 | 工具（Tool）、技能（Skill）以插件方式注册，按需启用 |

## 2. 总体架构

进程模型是**单进程双线程组**：JavaFX 持有 UI 线程并渲染窗口，Spring Boot 在内嵌 Tomcat
上提供 REST/SSE 接口。界面由 JavaFX 原生窗口承载，窗口内容区是一个 WebView 控件。

```

│  │  Stage「办公智能体」（原生窗口，可拖动/最小化/关闭）             │   │
```

### 为什么用 WebView 而不是 JavaFX 原生控件

**两条路都实际实现过**：先落地了纯 JavaFX 控件版（`ListView` + `TextFlow` + `TextArea`，
约 1300 行 Java + 150 行 CSS），功能跑通后回退到 WebView。决定性因素是样式与富文本能力：

| 需求 | JavaFX 原生控件 | WebView + HTML/CSS |
| --- | --- | --- |
| Markdown 表格 / 列表 / 粗体 | 要引 flexmark 再手写 AST → `TextFlow` 渲染器 | 引一个 md 库即可 |
| 代码块语法高亮 | 要 RichTextFX 或自己写 token 着色 | highlight.js 一行 |
| 公文模板 / 文档预览 / 图表 | 每种都得单独找库或手写 | 现成前端生态 |
| 样式迭代 | 改 CSS + 重启应用 | 改完 Ctrl+R 即时生效 |

代价是 32MB 的 WebKit 内核与多一层 HTTP 通信，换来的是后续 UI 迭代不再受控件能力限制 ——
对「公文写作、文档预览、数据表格分析」（见 3.2 的 P0 模块）这些强排版需求，这个交换是划算的。

> 原生控件版源码备份在 `C:\IDEAWorkSpace\_archive\fast-agent-javafx-native-ui-*.zip`，
> 其中的流式节流（50ms 定时器批量刷 Scene Graph）与消息气泡增量渲染实现可作参考。

### 传输层解耦

`ChatService` 不直接持有 `SseEmitter`，而是回调接口 `ChatListener`；web 层的
`SseChatListener` 负责把回调转成 SSE 事件。这样编排逻辑与传输方式无关，
换界面形态（原生控件 / 命令行 / 单元测试）时业务代码不用动。

## 4. 关键设计要点

### 4.1 流式通信

后端用 JDK `HttpClient` 解析模型侧 SSE，再经 `ChatListener` 回调交给 `SseChatListener`
转为 SSE 推给前端。前端因需携带请求体，用**异步 XHR 读取响应流**（`readyState=3`）逐帧解析 ——
WebKit 禁止主线程同步 XHR，必须异步。

`POST /api/chat/stream` 的事件流：

| 事件名 | 载荷 | 用途 |
| --- | --- | --- |
| `start` | `{sessionId}` | 回传真实 sessionId（新建会话时尤其必要） |
| `delta` | `{sessionId, delta, reasoning}` | 逐 token 渲染 |
| `done` | `{sessionId, content, reasoning}` | 生成结束，前端重载权威消息 |
| `error` | `{sessionId, message}` | 错误提示 |

**校验失败必须在 SSE 开始之前返回**：`startStream` 同步抛 `ApiException`，
由 `GlobalExceptionHandler` 返回 400 + JSON。若走 SSE 通道返回错误，前端只能拿到
一个看似成功的空流，表现为「发送后没有任何反应」。

兜底机制：前端同时 250ms 轮询 `GET /api/chat/snapshot/{sessionId}`。即使流通道异常，
回答内容仍能显示（仅在快照更长时覆盖，不会回退闪烁）。`POST /api/chat/stop` 用于中断生成。

**为什么不做渲染节流**：渲染在 WebView 里由浏览器负责，DOM 增量更新的代价远低于
JavaFX `TextFlow` 重排，无需额外节流。（原生控件版必须节流，见备份源码。）

### 4.2 上下文策略

`系统提示词 + 最近 N 轮消息`（N 默认 20，可配置）。后续升级为：**摘要压缩 + 向量检索召回**，突破长度限制。

### 4.3 本地存储

| 数据 | 位置 | 格式 |
| --- | --- | --- |
| 配置 | `~/.fast-agent/config.yaml` | YAML |
| 会话 | `~/.fast-agent/sessions.json` | JSON |
| 运行日志 | exe 同目录 `fast-agent.log` / `spring-boot.log` | 文本，4MB 轮转 |
| 知识库索引（规划） | `~/.fast-agent/kb/` | SQLite + 向量文件 |

### 4.4 安全边界

- 密钥仅存本机，界面脱敏；
- 默认不上传任何文件，文档解析在本地完成；
- 模型请求地址可配置，支持企业内网私有化模型；
- 内嵌服务只监听 `127.0.0.1`，不暴露到局域网。

## 6. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 启动速度 | 冷启动 < 4s（Spring 容器实测约 1.6s，加 JavaFX 窗口初始化约 2~3s） |
| 体积 | jpackage 产物约 171MB（含内嵌 JRE 与 WebKit 内核）；如需压缩，用 `jdeps` 裁 `--add-modules` 后回归测试 |
| 运行环境 | Windows 10 / 11 64 位；不依赖系统 WebView2（JavaFX 自带 WebKit） |
| 网络 | 仅需出网访问模型 API，支持代理 |
| 可靠性 | 流式中断可恢复提示；配置损坏自动回落默认值；端口冲突自动换端口重试 |
| 可维护性 | 界面/传输/业务三层分离（`ChatListener` 是传输边界），新增模型供应商仅需改配置预设 |
